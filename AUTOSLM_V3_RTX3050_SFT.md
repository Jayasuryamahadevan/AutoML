# AutoSLM v3: RTX 3050 4 GB SFT runbook

## Scope

This milestone implements a resumable-friendly, validation-selected QLoRA SFT run that exports a PEFT adapter. It does not implement from-scratch pretraining, continued pretraining, DPO, GRPO or a merged/quantized production model.

## Why this preset is conservative

- Base: Qwen2.5-0.5B-Instruct (change only after memory profiling).
- 4-bit NF4 with double quantization.
- FP16 compute; no BF16 assumption.
- Per-device microbatch: 1.
- Gradient accumulation: 8.
- Sequence length: 512.
- LoRA rank: 8, alpha: 16.
- Gradient checkpointing.
- Paged 8-bit AdamW.
- Evaluation and checkpoint save every 25 steps; best checkpoint selected by validation loss.
- Locked test evaluated after best-checkpoint restoration and never used for training decisions.

These are initial conservative settings, not a guarantee of fit. Windows background GPU use, model loading overhead, Transformers versions and CUDA/bitsandbytes builds change memory use. If CUDA OOM occurs, reduce sequence length to 384 or 256 first, then use a smaller compatible base model. Do not silently reduce test coverage or remove evaluation.

## Environment

Use a clean Python 3.10/3.11 CUDA environment. Install a PyTorch build compatible with the installed NVIDIA driver first, then install the repository requirements. Verify:

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'no CUDA')"
python -c "import bitsandbytes as bnb; print(bnb.__version__)"
```

The code uses Transformers Trainer + PEFT directly. TRL is not required for this first SFT milestone.

## Dataset format

JSONL, one object per line. Supported fields:
- `instruction` + `response`
- `prompt` + `completion`
- `instruction` + optional `input` + `output`
- `messages` with user/system and assistant roles

Supply a `group_id` or source document ID to keep related examples in the same partition. The splitter also groups identical prompts. The current split occurs after examples have been assembled; for rigorous generalization claims, partition raw source documents before synthetic augmentation and keep an externally curated locked test set.

## Run

```bash
python -m pip install -r requirements.txt
python scripts/train_sft.py --dataset data/train_examples.jsonl --config configs/autoslm_v3_rtx3050.json
```

Artifacts are written under `outputs/autoslm_v3/<run-id>/`:
- `splits/`: train, validation, test JSONL
- `checkpoints/`: Trainer checkpoints
- `adapter/`: PEFT adapter and tokenizer
- `experiment_manifest.json`: model/config/data/runtime metadata
- `lineage.sqlite3`: hash-chained run events
- `result.json`: training, validation and locked-test metrics

## Verification gates

1. Run CPU-only unit tests: `python -m pytest tests -q`.
2. Verify CUDA and bitsandbytes imports.
3. Run a small real training job on the 3050.
4. Confirm adapter files exist and can be loaded with PEFT.
5. Confirm validation loss was used for checkpoint selection and test metrics were emitted only after training.
6. Record peak VRAM and wall-clock time from the real device run before claiming the preset is validated.

## Important limitations

- No automatic resume command yet; Trainer checkpoints are saved, but resuming is not yet exposed by this CLI.
- The test set is generated by the current group-aware splitter; it is not automatically human-curated or independently sourced.
- The code assumes the model architecture exposes the configured LoRA module names. Verify target modules for any different base model.
- The trainer does not publish to Hugging Face Hub or deploy to Ollama.
